# Safe Push

변경사항을 지정한 브랜치로 **검증 단계를 거쳐** 푸시하는 오케스트레이터 스킬이다. 단순 `git push`가 아니라, 시크릿 유출·미검증 코드가 원격에 올라가는 것을 구조적으로 막는다.

## 파이프라인

```
0. 브랜치 준비   — 대상 브랜치 확인. 없으면 생성, 있으면 전환.
1. 시크릿 스캔   — [secret-scan]   (Haiku 서브에이전트)  발견 시 ❌ 중단
2. 테스트        — [test-writer]   작성+실행, 실패/취약점 시 ❌ 중단
3. 커밋          — [commit-writer] (Haiku 서브에이전트)  메시지 생성 + 커밋
4. 푸시          — 대상 브랜치로 push (신규면 upstream 설정)
```

**각 단계는 게이트다.** 앞 단계가 실패하면 다음으로 넘어가지 않고, 무엇이 왜 막혔는지 보고하고 멈춘다. 통과한 단계까지는 살려둔다(예: 브랜치는 만들어졌고 커밋도 됐는데 푸시만 실패 → 그 상태를 알리고 재시도 안내).

각 단계는 해당 스킬의 지침을 따른다. 그 스킬 파일을 읽어 그대로 수행한다.

## 의존 스킬

| 스킬 | 구분 | 없을 때 설치 명령 | 출처 |
|---|---|---|---|
| `secret-scan` | 필수 | `npx skills add dahun428-fx/work_tools --skill secret-scan -g -a claude-code -y` | https://github.com/dahun428-fx/work_tools/tree/main/skills/secret-scan |
| `test-writer` | 필수 | `npx skills add dahun428-fx/work_tools --skill test-writer -g -a claude-code -y` | https://github.com/dahun428-fx/work_tools/tree/main/skills/test-writer |
| `commit-writer` | 필수 | `npx skills add dahun428-fx/work_tools --skill commit-writer -g -a claude-code -y` | https://github.com/dahun428-fx/work_tools/tree/main/skills/commit-writer |

실행 전에 각 스킬이 설치돼 있는지 확인한다 — `~/.claude/skills/<이름>/SKILL.md` 또는 프로젝트의 `.claude/skills/<이름>/SKILL.md`.
없으면 사용자에게 "○○ 스킬이 없습니다. 설치할까요?"라고 한 번 묻고, 승인하면 표의 설치 명령을 그대로 실행한 뒤 설치된 SKILL.md를 읽고 이어서 진행한다. 설치를 거절하면 아래 본문의 요약 기준으로 수행하고 "○○ 스킬 없이 기본 동작으로 진행했다"고 알린다.

## 0. 브랜치 준비

사용자가 말한 대상 브랜치 이름을 파악한다 (예: "feature/login 브랜치로 푸시"). 이름이 없으면 **묻는다** — 어떤 브랜치에 올릴지 추측하지 않는다.

대상 브랜치를 다음 규칙으로 준비한다:

- **현재 브랜치와 같으면**: 그대로 진행.
- **로컬에 이미 있으면**: 그 브랜치로 전환(`git switch <branch>`). 작업 중 변경이 전환을 막으면(충돌) 사용자에게 상황을 알리고 멈춘다 — 임의로 stash/버리지 않는다.
- **로컬에 없으면**: **현재 변경을 가진 채 새로 만든다** (`git switch -c <branch>`). 이러면 작업 내용이 새 브랜치로 따라온다.
- 원격에만 있고 로컬에 없으면: 원격을 추적하는 브랜치로 체크아웃한다.

> 보호 브랜치(main 등)로 직접 푸시하려는 경우, 정책상 막힐 수 있음을 미리 환기하고 feature 브랜치 + MR을 제안할 수 있다. 단, 사용자가 명시한 대상은 존중한다.

## 1. 시크릿 스캔 (게이트 · Haiku로 실행)

이 단계는 **Haiku 모델(`claude-haiku-4-5`)로 도는 서브에이전트에 위임**한다. 시크릿 스캔은 패턴 매칭 위주의 가볍고 반복적인 작업이라, 빠르고 저렴한 Haiku가 적합하다. Task/Agent 도구로 서브에이전트를 띄울 때 `model: haiku`를 지정하고, `secret-scan/SKILL.md`의 지침에 따라 변경분을 점검하게 한다.

서브에이전트는 스캔 결과(clean / 발견 목록)를 구조적으로 돌려주고, 이 오케스트레이터가 게이트를 판정한다. **시크릿이 발견되면 중단**한다 — 커밋도 푸시도 하지 않는다. 발견 항목(마스킹된 위치·위험도·개선점)을 보고하고, 제거 후 다시 시도하도록 안내한다. 이미 푸시 이력이 있는 값이면 폐기·재발급을 권고한다.

clean이면 다음 단계로.

## 2. 테스트 (게이트)

`test-writer`를 변경분+영향 범위에 대해 수행한다 — 테스트 작성, **직접 실행**, 보안 점검까지. 
- **테스트가 실패**하면 중단하고 원인·개선점을 보고한다. 깨진 채로 커밋/푸시하지 않는다.
- **보안 취약점**이 발견되면 위험도와 함께 보고하고 중단한다 (사용자가 "그래도 진행"이라고 명시하면 진행 가능).
- 테스트를 실행할 환경이 없으면(러너 미설치 등) 그 사실을 알리고, 계속할지 사용자에게 확인한다.

모두 통과하면 다음 단계로.

## 3. 커밋 (Haiku로 실행)

이 단계도 **Haiku 모델(`claude-haiku-4-5`) 서브에이전트에 위임**한다. diff에서 짧은 한 줄 메시지를 뽑는 가벼운 작업이라 Haiku가 적합하다. Task/Agent 도구로 `model: haiku`를 지정하고 `commit-writer/SKILL.md` 지침을 맡긴다.

`commit-writer`로 변경을 커밋한다 — "영어 동사: 한글 요약(~30자)" 형식의 한 줄 메시지를 생성해 커밋한다. 스테이징 규칙(임의 `git add .` 금지)은 commit-writer를 따른다. 커밋 후 메시지·해시를 보여준다.

## 4. 푸시

대상 브랜치를 원격으로 푸시한다.
- 원격에 처음 올리는 브랜치면 upstream을 설정: `git push -u origin <branch>`
- 이미 추적 중이면: `git push`
- 결과(브랜치, 푸시된 커밋, 원격 응답)를 보여준다. GitLab/GitHub가 MR/PR 생성 링크를 응답에 주면 함께 안내한다.
- 푸시가 거부되면(보호 브랜치, non-fast-forward 등) 원인을 그대로 보여주고 다음 선택지를 제시한다 — 임의로 force-push 하지 않는다.

## 한 줄 요약

> "○○ 브랜치로 푸시" 요청에, 브랜치를 준비하고 시크릿 스캔 → 테스트 → 커밋 → 푸시를 게이트로 실행한다. 시크릿·테스트 실패 시 멈추고, 보호 브랜치 거부 시 force하지 않는다.
