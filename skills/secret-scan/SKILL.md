# Secret Scan

코드에 **하드코딩된 비밀**(자격증명)이 들어갔는지 탐지하고, 커밋/푸시 전에 막는 스킬이다. 한 번 유출된 시크릿은 git 히스토리에 영구히 남아 회수가 매우 어렵기 때문에, **커밋 전에 잡는 것**이 핵심이다.

> **실행 모델**: 이 스킬은 패턴 매칭 위주의 가벼운 작업이므로 **Haiku 모델(`claude-haiku-4-5`)에서 도는 것을 권장**한다. `safe-push` 파이프라인은 이 단계를 Haiku 서브에이전트로 위임해 실행한다. 직접 호출할 때 빠르게 돌리고 싶으면, Haiku로 도는 서브에이전트(Task/Agent 도구, `model: haiku`)에 이 지침을 맡겨도 된다.

## 진행 방식

1. **스캔 범위 결정**
   - 기본: `git diff --staged`(스테이징됨) → 없으면 `git diff`(작업 변경분). 커밋/푸시 직전 점검이 주 용도이므로 **추가된 라인(`+`)**에 집중한다.
   - 사용자가 파일/디렉토리를 지정하면 그 범위를 스캔한다.
   - 추적되지 않은 새 파일(`git status`의 untracked)도 빠뜨리지 말 것 — `.env` 같은 게 실수로 들어오는 경로다.

2. **탐지** — 아래 유형을 찾는다.

3. **오탐 걸러내기** — 진짜 비밀과 플레이스홀더를 구분한다.

4. **보고** — 값은 마스킹해서, 위치·유형·위험도·개선점을 제시한다.

5. **판정** — clean(이상 없음) / found(발견, 차단 권고).

## 무엇을 탐지하나

- **클라우드 키**: AWS Access Key(`AKIA...`)·Secret, GCP 서비스 계정 키(JSON), Azure 키
- **서비스 토큰**: GitHub(`ghp_`, `github_pat_`), Slack(`xoxb-`, `xoxp-`), Stripe(`sk_live_`), OpenAI(`sk-`), Google API 키(`AIza...`) 등 알려진 접두사
- **개인키/인증서**: `-----BEGIN ... PRIVATE KEY-----` 블록
- **자격증명 할당**: `password`, `passwd`, `pwd`, `secret`, `api_key`, `apikey`, `token`, `access_key` 등의 변수/키에 **문자열 리터럴**이 직접 대입된 경우
- **접속 문자열**: 자격증명 포함 URI (`postgres://user:pass@host`, `mongodb://...:...@`, `redis://:password@`)
- **JWT / 고엔트로피 문자열**: 의심스러운 이름에 붙은 긴 base64/hex 토큰
- **민감 파일 유입**: `.env`, `id_rsa`, `*.pem`, `credentials.json` 등이 변경분/추적대상에 포함됐는지

## 오탐(false positive) 구분

다음은 비밀이 아니므로 **시끄럽게 잡지 않는다** (다만 애매하면 낮은 위험도로 언급):

- 플레이스홀더: `your_api_key`, `changeme`, `xxx`, `<token>`, `example`, `dummy`, `placeholder`, `REPLACE_ME`
- 환경변수/시크릿 매니저 참조: `process.env.X`, `os.environ[...]`, `${SECRET}`, Vault/SSM 조회 등 — **이건 올바른 패턴이므로 통과**
- 명백한 테스트 픽스처의 가짜 값 (단, 진짜처럼 생긴 라이브 키 형태면 의심한다)

핵심 판단: **"이게 실제로 외부 시스템에 인증되는 살아있는 값인가?"** 그렇다면 잡고, 자리표시자면 넘긴다.

## 보고 형식

발견한 각 항목을 아래처럼 보고한다. **값은 절대 전체를 출력하지 말고 마스킹**한다 (앞 4자 정도만, 나머지는 `****`). 로그에 또 남기지 않기 위함이다.

```
🔑 시크릿 발견: {유형 — 예: AWS Access Key}
위치: {파일:라인}
값: {앞 4자}**** (마스킹)
위험도: 높음 / 중간 / 낮음
개선점: {코드에서 제거 → 환경변수/시크릿 매니저로. 이미 커밋/푸시된 적 있으면 해당 키를 즉시 폐기·재발급(rotate)하고 히스토리에서 제거}
```

**중요**: 만약 그 시크릿이 이미 원격에 푸시된 이력이 있다면, 단순 삭제로 끝나지 않는다 — **노출된 것으로 간주하고 키를 폐기·재발급**해야 한다고 분명히 알린다. git 히스토리에 남은 값은 누구나 볼 수 있다.

## 판정과 마무리

- **clean**: "시크릿 스캔: 발견 없음"을 한 줄로 보고하고 통과.
- **found**: 발견 목록을 보고하고, **커밋/푸시를 진행하지 말 것을 권고**한다. (파이프라인에서 호출된 경우, 다음 단계로 넘어가지 않도록 실패로 알린다.)

도구가 있으면 활용해도 좋다(`gitleaks`, `trufflehog` 등). 없으면 위 패턴 기반으로 직접 점검한다 — 도구 유무와 무관하게 동작해야 한다.

## 한 줄 요약

> 변경분의 추가 라인에서 하드코딩된 자격증명을 찾아, 마스킹해 위치·위험도·개선점을 보고하고, 발견 시 커밋/푸시를 막는다. 이미 푸시된 시크릿은 폐기·재발급을 권고한다.
