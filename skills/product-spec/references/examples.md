# 좋은 서술의 실제 수준

실무 기획서에서 뽑은 예시. 추상적인 조언보다 실제 문장의 밀도를 보는 편이 빠르다.
왼쪽은 흔히 쓰는 수준, 오른쪽은 되물을 것이 남지 않는 수준이다.

## 목차

1. 경계조건
2. 제외·충돌 케이스
3. 카운트와 재발 조건
4. 리스크 서술
5. 마이크로카피
6. 정책(금지 규칙)
7. 케이스 매트릭스 한 열
8. 대안 판단
9. 입력 데이터 필수 여부
10. 목적 서술

## 1. 경계조건

> ❌ 14일 동안 노출한다.

> ✅ 리포트 도착 CASE는 신규 월간 리포트가 정상적으로 제공 가능한 상태가 된 날을 포함하여 총 14일간 노출한다.
> 결과 제공 가능일을 포함한 14일째 23:59:59까지 적용하고, 15일째 00:00부터 종료한다. **모든 일시는 KST를 기준으로 한다.**

포인트: 기산일이 무엇인지(제공 가능일), 포함인지 제외인지(포함하여), 끝나는 순간(23:59:59), 다음 상태 시작(15일째 00:00), 타임존.

## 2. 제외·충돌 케이스

> ✅ 기존 CASE의 상태 및 노출 이력과 관계없이 새로운 리포트가 제공 가능해지면 해당 제공 가능일을 기준으로 새로운 14일을 산정한다.

> ✅ 여러 계좌·카드의 신규 리포트가 같은 날 제공 가능해지면 해당 날짜를 기준으로 한 번만 14일을 산정한다.

> ✅ 동일 결과 재전송, 단순 정정, 재분석, UI 변경 및 장애 복구는 신규 결과로 인정하지 않으며 기존 종료일을 변경하지 않는다.

> ✅ 노출 대상 결과가 삭제되거나 제공 불가 상태로 변경되면 다른 유효한 신규 결과의 존재 여부에 따라 CASE를 다시 판단한다. 유효한 결과가 없으면 도착 CASE를 즉시 종료한다.

포인트: 정상 흐름은 누구나 상상한다. 기획자만 정해줄 수 있는 것은 **"이건 새 것으로 안 친다"**는 목록이다. 운영 사고는 대부분 여기서 난다.

## 3. 카운트와 재발 조건

> ❌ 일정 횟수 사용 후 피드백을 요청한다.

> ✅ 2회 발화(**사용자 turn만 카운트**) 시 노출 — 답변이 없을 시 이후 **매 2회 발화마다** 노출

> ✅ 매 세션별 최초 3회 발화 후 노출

> ✅ 다시 N회차 사용의 요청 정책을 따름. **+30일 정의 예시** — 만약 7월 1일 피드백 제출이 이루어진 경우 7월 31일 0시부터 피드백 요청 조건에 다시 해당됨

포인트: 무엇을 세는지(사용자 turn만), 반복 주기, 그리고 **날짜를 넣은 예시 한 줄**. 예시가 있으면 오프바이원 논쟁이 사라진다.

## 4. 리스크 서술

> ❌ 미확정 시 일정이 지연될 수 있음

> ✅ AI 상담 진입 채널이 없어 별도 앱·별도 웹 구축 논의로 확장될 수 있음 / 대전제가 흔들림

> ✅ 타인 열람·개인정보 노출 위험, 결과 연동 불가

> ✅ 카드사 명세서와 AI 상담 표현이 달라 사용자 혼란 및 신뢰 저하 발생

> ✅ 잘못된 사용자에게 결과가 연결되거나 중복 계정 발생 가능

> ✅ 단순 정보조회 서비스로 끝나 재방문·유료 전환 효과가 약해짐

포인트: 리스크는 **무엇이 깨지는가**다. "지연", "혼란" 같은 추상명사로 끝내지 않고 깨지는 대상을 지목한다.

## 5. 마이크로카피

기획서가 확정해야 할 문구의 범위를 보여주는 예. 버튼 라벨만이 아니라 상태 문구 전부다.

| 상황 | 확정 문구 |
|---|---|
| 헤드 카피 (신규) | "새 월간 리포트가 도착했어요" |
| 헤드 카피 (환기) | "지난달 소비 리포트를 확인해 보세요" |
| 헤드 카피 (기본) | "소비와 예산에 대해 궁금한 점을 물어보세요" |
| 긍정 피드백 후 | "도움이 되어 다행입니다 🍀" |
| 부정 피드백 후 | "다음엔 더 좋은 답변을 준비할게요 😢" |
| 상세 의견 유도 | "자세한 의견 남기기 >" |
| 옵션 선택지 | "더 쉽게 설명해 주세요" / "핵심만 요약해 주세요" / "더 자세히 설명해 주세요" |
| 로딩 | "더 쉽게 답변을 재생성중입니다.." / "핵심만 짧게 요약중입니다.." |
| 완료 태그 | "더 쉽게 설명한 답변" / "핵심만 요약한 답변" / "새로 정리한 답변" |

같은 기능의 세 문구(선택지·로딩·완료 태그)가 서로 호응하는지 확인한다. "더 쉽게 설명해 주세요" → "더 쉽게 답변을 재생성중입니다.." → "더 쉽게 설명한 답변"처럼 어휘가 이어져야 사용자가 자기가 무엇을 눌렀는지 기억한다.

동작 규칙도 문구만큼 구체적으로 적는다:

> ✅ null 입력창도 제출 가능
> ✅ 선택 시 text 입력창에 내용 기입 여부와 상관없이 팝업 닫기
> ✅ text 입력 내용 저장 > 토스트로 저장 완료 안내

## 6. 정책(금지 규칙)

> ✅ FE/LLM에서 계산하지 않으며, BE 산출 결과만 사용

> ✅ 투자 권유, 수익 보장, 특정 금융상품 추천 표현 금지

> ✅ 최초 질문의 목적과 현재 Intent를 유지한다. 재생성 옵션이 질문의 범위를 바꾸지 않는다.

> ✅ 거래 내역, 금액, 분류 결과, 사용자 자산정보, 승인된 근거 문서의 사실을 변경하지 않는다.

> ✅ 대출·투자 실행 지시, 세무 판단, 신용등급 변동 예측을 단정적으로 제공하지 않는다.

> ✅ 사용자가 묻지 않은 상품, 투자, 절세 주제로 과도하게 확장하지 않는다.

포인트: 전부 "~하지 않는다" 형태다. 하지 않을 일의 목록이 있어야 구현자가 선의로 기능을 넓히는 것을 막는다.

## 7. 케이스 매트릭스 한 열

한 케이스가 이 정도로 채워져야 개발·디자인이 각자 자기 몫을 가져간다.

| 구분 | 리포트 도착 CASE |
|---|---|
| 노출 조건 | 신규 월간 리포트 생성 후 공통 NEW 기간인 14일 동안 노출 |
| 사용자 니즈 | 새 리포트에서 무엇을 확인해야 할지 알고 싶음 |
| 목적 | 신규 리포트 인지 및 리포트 기반 탐색 유도 |
| 헤드 문구 | "새 월간 리포트가 도착했어요" |
| 콘텐츠 | 새 리포트 기반 예산 초과 항목, 고정지출 추이, 전월 대비 분석 |
| 사용자 액션 | 리포트 상세 확인 > 관련 내용 추가 질문 |
| 성격 | 신규 리포트 중심의 기간 한정형 안내 |

"성격" 행이 특히 유용하다. 그 케이스가 **왜 존재하는지**를 한 줄로 요약하므로, 나중에 케이스를 추가·삭제할 때 판단 기준이 된다.

## 8. 대안 판단

| 대안 | 장점 | 문제점 | 판단 |
|---|---|---|---|
| 7일 | 신규성 유지, 기본 랜딩으로 빠르게 전환 | 저빈도 사용자는 도착 CASE를 보지 못할 가능성이 큼 | 다소 짧음 |
| 14일 | 신규성·접근 기회·운영 단순성 간 균형 | 사용빈도가 매우 낮으면 미노출 가능 | 초기 권장 |
| 30일 | 리포트 확인 기회가 넓음 | 다음 달 리포트가 나올 때까지 지난 리포트를 계속 '새 리포트'로 표현하게 됨 | 다소 김 |
| 무기한 | 대부분의 사용자에게 노출 가능 | 일시적 랜딩이라는 목적이 약해지고 기존 문제 반복 | 비권장 |

포인트: 판단 칸이 한 단어라 표를 훑기만 해도 결론이 보인다. 그리고 기각 사유가 남아 있어 같은 대안이 다시 올라오지 않는다.

## 9. 입력 데이터 필수 여부

| 데이터 | 활용 목적 | 필수 여부 |
|---|---|---|
| 사용자 질문의 핵심 의도 | 사용자의 원래 질문 의도를 유지하기 위한 기준 | 필수 |
| 표현 난이도 | 답변 난이도·길이·구조를 결정 | 필수 |
| 개인 소비데이터 | 소비 내역 분석, 예산, 고정지출 질문에 개인화 적용 | 조건부 필수 |
| 직전 대화 맥락 | 답변 해석에 필요한 경우에만 활용 | 조건부 |
| 이전 답변 | 반복 표현 방지 또는 차별화 참고용 | 선택 |

포인트: 조건부 항목은 **조건을 활용 목적 칸에 함께** 적는다. "조건부 필수"라고만 쓰면 언제 필요한지가 사라진다.

## 10. 목적 서술

> ✅ 리포트 생성 직후에는 새로운 결과와 관리 필요 항목을 빠르게 확인하고, 평상시에는 현재 궁금한 소비·예산 문제를 자유롭게 질문할 수 있도록 한다.
> ✅ AI 상담의 역할을 '월간 리포트 해석'에서 '지속적인 개인 재무관리 지원'으로 확장한다.
> ✅ 월 1회 리포트 확인에 그치지 않고, 반복적으로 이용할 수 있는 서비스 구조를 마련한다.

포인트: 세 문장이 각각 다른 층위를 말한다 — 사용자 경험, 제품 역할, 사업 구조. 목적을 여러 개로 쪼갤 때는 같은 말을 바꿔 쓰지 말고 **층위를 달리한다.**

그리고 목적 앞에 문제 인식이 온다:

> ✅ 최근 리포트 중심의 랜딩 화면은 리포트 생성 직후에는 유용하지만, 시간이 지난 뒤에도 동일한 결과의 반복노출로 서비스의 범위를 오히려 한정시키는 역효과를 준다.

포인트: 현행을 부정만 하지 않고 **"~에는 유용하지만"**으로 조건을 인정한 뒤 한계를 짚는다. 기존 결정을 내린 사람을 적으로 만들지 않으면서 변경 근거를 세우는 방식이다.
